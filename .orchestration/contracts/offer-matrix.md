### Bookable meeting types

`meeting_types` fixes the two bookable types. Their IDs are the `bookings.offer_id` values proposed in `operational-data-model.md` (the validation script checks this).

| Meeting type | Belongs to offer | Minutes | Needs a consultation right |
|---|---|---|---|
| `intro-15` | `intro-15` | 15 | no |
| `book-consultation-30` | `book-bundle` | 30 | yes (one `consultation_rights` row per verified paid order) |

60 minutes cannot appear anywhere a duration is defined. `offers.intro-15.duration_minutes`, `offers.book-bundle.included_consultation.duration_minutes` and `meeting_types.*.duration_minutes` are all `const` (OM-DUR-1 to OM-DUR-3). ## 2. Pending versus recorded

Every value that G0, G1 or G5 must decide uses the same shape:

```json
{ "status": "pending", "value": null, "approvals": [] }
{ "status": "recorded", "value": <typed value>, "approvals": [{ "gate": "G0", "record_id": "gr-01" }] }
```

- `pending` forces `value: null` and no approvals. **A price, cap or other value written while pending is an invented value** (OM-PRICE-1).
- `recorded` needs a typed value and approvals naming every required gate for that field (OM-PRICE-2, OM-CAP-1). Each approval points at an entry of `gate_records`.
- `gate_records[]` holds `record_id`, `gate`, `covers`, `record_ref`, `recorded_by_role` and `recorded_on`. `recorded_by_role` is a human gate owner only: `arnaud`, `bill`, `firm_reviewer`, `privacy_owner` or `account_owner`. An agent role is refused (OM-DOC-2).
- `document_kind: authoritative` accepts `record_ref` only as `.orchestration/decisions.md#D-nnn` (a G0 answer that A0 transcribed with its date and who gave it, per blockers.md "How to answer") or `.orchestration/approval-packets/…` (H00, proposed). `fixture:` references are refused (OM-DOC-1). `document_kind: fixture` accepts only `fixture:` references, so fixture values can never pass as real ones.
- Proposals from the plan are kept apart from recorded values, as `const` fields next to the gated value: `cap.proposal_bundles = 8`, `entitlement.unit.proposal = "one_household_per_bundle"`, and `capacity_proposal` (6 introductions and 2 book meetings a week, each with a 10-minute buffer). G0 or G1 may record something different. The proposal never becomes the value by default.

Gated values and their gates:

| Field | Gates | Typed value when recorded | Question that feeds it |
|---|---|---|---|
| `book-bundle.price` | G0 | `{amount_minor: integer ≥ 1, currency: ISO 4217}` | HB-20 (**no price exists anywhere and none is proposed**, D-032) |
| `book-bundle.cap` | G0 | integer ≥ 1 | HB-20 (proposal 8) |
| `book-bundle.entitlement.unit` | G1 | unit key, for example `one_household_per_bundle` | HB-20, HB-24 (D-007) |
| `included_consultation.validity` | G0 | `{unit: days\|months, count}` | HB-20 |
| `*.capacity_per_week` | G0 | integer ≥ 1 | HB-16 (D-033) |
| `*.in_person_location` | G0 | location key (the address stays in `lib/business.ts` once `businessDetails` is approved) | HB-16 |
| `*.online_service` | G0 | service key; anything containing `zoom` is refused (OM-MOD-2, D-008) | HB-14, HB-15 |
| `prepayment_disclosures.price`, `.currency`, `.tax_treatment` | G0 | `{wording_asset_id: "copy.<key>"}` | HB-20 |
| `prepayment_disclosures.shipping` | G0, G5 | same | HB-20, HB-28 |
| `prepayment_disclosures.eligibility` | G1 | same | HB-24 |
| `prepayment_disclosures.booking` | G0, G1 | same | HB-16, HB-24 |
| `prepayment_disclosures.cancellation`, `.refund` | G1, G5 | same | HB-24, HB-28 |
| `approved_editions[]`, `approved_print_editions[]` | G3 | `{locale, sha256}` of the exact file | HB-04, H00 |

A disclosure's value points at the approved wording in the asset manifest (`copy.<key>`, asset-manifest 1.0). That wording asset needs its own G1 and G3 approval (approval-scopes.md).

## 3. Modalities

`modalities_permitted` is fixed at `["online", "in_person"]`: the frozen offer allows both. `modalities_offered` is what may be presented **now**. It is empty today.
- `in_person` may be offered only when `in_person_location` is recorded (OM-MOD-1; 01 §11: in person only once Bill's location and room are confirmed).
- `online` may be offered only when `online_service` is recorded (OM-MOD-3). HB-15 asks which video tool the existing Calendly remote type uses. It could be Zoom, which is forbidden, so online stays unconfirmed until G0 answers.

This does not stop local building or the existing Calendly link, which stays live during the build (D-024, D-062). It stops any new copy, email or page from presenting a modality that has not been confirmed.

## 4. Book sale states

`book-bundle.sale_state` is one of:
- `not_on_sale`: the state today.
- `test_mode_only`: Stripe test mode behind review protection, with a product marked TEST and no public price (D-032, HB-20 fallback). Allowed while terms are pending.
- `on_sale`: needs, in the same document, price, cap, entitlement unit, consultation validity and capacity recorded, at least one approved print edition, at least one confirmed consultation modality, and all eight disclosures recorded (OM-SALE-1).

`on_sale` in this document does not switch anything on. Live checkout also needs the `checkout_live` flag and its gates G0, G1, G2, G3, G5 and G6 (feature-flags.md), and the capped book-sales rollout step (D-036).

## 5. Entitlement rules (frozen)

- One consultation right per verified paid order (`rights_per_verified_paid_order = 1`, OM-BOOK-2). Issued only from `book.payment_confirmed` with source `provider.stripe_webhook` (event-envelope.md), never from a redirect or its query string, a hidden or reusable scheduling URL, a click, or a second webhook or checkout session (authority-matrix.md AM-PAY-1, AM-PAY-2, AM-RIGHT-1).
- Rescheduling moves the existing right. A refund voids an unused right as the approved terms say (HB-20, HB-28).
- `separately_priced = false` (OM-BOOK-1): the promise is "30 minutes included", not a service with an invented value.
- `survives_no_fit = true` and `removable_by_fit_screen = false` (OM-BOOK-3): a buyer keeps the consultation even when no ongoing relationship follows.
- The 30 minutes are also enforced where data is stored: `consultation_rights.duration_minutes = 30` and the bookings duration checks (operational-data-model.md, AM-RIGHT-2).

## 6. No mandatory funnel staircase

`rules.no_mandatory_funnel_staircase`:
- `intro_15_prerequisites` must be empty (OM-FUNNEL-1). Nobody has to watch a webinar, finish the workshop or buy the book before asking Bill a question (01 §1, D-005).
- `must_link_to_meeting` lists the route keys whose pages must offer a direct link to the 15-minute meeting: `home`, `retirement`, `investments`, `about`, `resources`, `fees`, every article page, `workshop`, `crossroads`, `crossroadsConfirmed`, `crossroadsReplay` and `book`. Keys are defined in routes.md.
- `exempt_from_meeting_link`: `meeting` (it is the meeting page), `privacy` and `legal` (the existing code already hides the CTA there: `StandardPage` in `components/pages.tsx` sets `cta` false for `meeting`, `privacy` and `legal`), `emailPreferences` and `unsubscribe` (no solicitation while someone withdraws), and `crossroadsJoin`, `bookOrderStatus` and `bookConsultation` (the person is already in a flow). Exempt means no extra call to action in the page body. The site-wide header, which on main and codex shows a meeting button on every page (`components/navigation.tsx`), stays.
- `workshop_ending_useful_without_email_or_booking = true` (01 §9, WK07).

The free PDF never requires marketing consent or an email address, and stays downloadable when email fails (`access` const, OM-PDF-1; D-001).

## 8. How downstream tasks use it

- **U02** (meeting): presents `intro-15` with exactly 15 minutes and one question, and only the modalities that `modalities_offered` confirms. It keeps the existing Calendly link until a replacement is proven (D-024). A booking counts only from the provider or an operator reconciliation.
- **U03 and N05** (book): Stripe product and checkout come only from recorded price and currency. No checkout session in live mode unless `sale_state = on_sale` and `checkout_live` is enabled. One right per order, 30 minutes.
- **C06, C07, C09** (copy): every offer statement carries `offer_refs` in the asset manifest, so a change to this matrix invalidates exactly the dependent approvals (approval-scopes.md §6).
- **W01 to W04** (workshop): the ending offers the local summary, the guide and the 15-minute meeting, with nothing required first.
- **R00**: checks that every `must_link_to_meeting` page renders a meeting link.

## 10. Versioning

Changing an offer is outside every agent's authority (D-001 to D-005, CHANGE_CONTROL const). If Arnaud and Bill change one explicitly, A0 records it in `decisions.md` and issues `2.0` for a change of meaning, or `1.1` for an addition consumers can reject safely. Every asset whose `offer_refs` names the changed offer loses its approval (approval-scopes.md). Recording a G0 value (for example a price) is not a contract change: it updates the authoritative instance and invalidates only assets that state that value.
